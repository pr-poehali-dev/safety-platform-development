# План переезда АРМ «Охрана труда» на serv.host

Тариф: 4 ГБ / 2 ядра / 40 ГБ NVMe, Ubuntu 24.04, локация Москва или Новосибирск.
Ориентировочное время: 1-2 рабочих дня. Простой для пользователей: 1-2 часа в момент переключения.

## Важно знать заранее

1. Сейчас серверная часть работает как набор отдельных облачных функций на платформе. На обычном сервере они сами не запустятся: нужен небольшой «переходник», который принимает запросы и вызывает те же функции. Его нужно написать и проверить (шаг 4).
2. Фото нарушений лежат в хранилище платформы, ссылки на них записаны в базе. При переезде файлы нужно скачать, положить на новый сервер и заменить ссылки в базе (шаг 6).
3. База небольшая (около 5 МБ, 35 таблиц), переносится быстро.
4. ИИ-помощник использует ключ Gemini (Google). Из РФ без обходных путей он может не работать, а запросы уходят за границу. Если требование «вся информация в РФ» касается и этого, помощника нужно отключить или заменить на российскую модель.

## Шаг 0. Подготовка (до заказа)

- Заказать сервер: Ubuntu 24.04, публичный IPv4, нужная локация.
- Завести домен (или использовать существующий) и направить A-запись на IP сервера.
- Завести российское облачное хранилище для резервных копий (Yandex Object Storage или Selectel), создать бакет и ключ доступа.
- Уточнить у serv.host письменно размещение данных в РФ.

## Шаг 1. Первичная настройка сервера

Подключиться по SSH под root и выполнить:

```
apt update && apt upgrade -y
adduser deploy
usermod -aG sudo deploy
rsync --archive --chown=deploy:deploy ~/.ssh /home/deploy
```

Дальше работать под пользователем `deploy`. Затем:

```
sudo apt install -y nginx postgresql python3-venv python3-pip git ufw certbot python3-certbot-nginx rclone
sudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'
sudo ufw enable
```

Рекомендуется отключить вход по паролю (`PasswordAuthentication no` в `/etc/ssh/sshd_config`) после проверки входа по ключу.

## Шаг 2. База данных

```
sudo -u postgres psql -c "CREATE USER arm WITH PASSWORD 'ПРИДУМАЙТЕ_ПАРОЛЬ';"
sudo -u postgres psql -c "CREATE DATABASE arm OWNER arm;"
```

Строка подключения для приложения:
`postgresql://arm:ПАРОЛЬ@localhost:5432/arm`

Порт базы наружу не открывать.

## Шаг 3. Выгрузка данных со старой платформы

Нужна строка подключения старой базы (секрет `DATABASE_URL` проекта). Со своего компьютера:

```
pg_dump "СТАРАЯ_DATABASE_URL" --schema=t_p5901577_safety_platform_deve --no-owner --no-privileges -Fc -f arm.dump
```

Передать файл на сервер:

```
scp arm.dump deploy@IP_СЕРВЕРА:~/
```

Загрузить на новом сервере:

```
pg_restore --no-owner -d "postgresql://arm:ПАРОЛЬ@localhost:5432/arm" arm.dump
```

Схема в базе сохранит прежнее имя, поэтому код функций менять не придётся.
Проверка: `psql ... -c "\dt t_p5901577_safety_platform_deve.*"` должна показать 35 таблиц.

## Шаг 4. Серверная часть

1. Выгрузить проект через «Скачать → Скачать код» или GitHub и склонировать на сервер в `/opt/arm`.
2. Создать окружение и поставить зависимости всех функций:
   ```
   cd /opt/arm
   python3 -m venv venv
   venv/bin/pip install gunicorn flask psycopg2-binary boto3 openpyxl Pillow
   ```
3. Создать переходник (`server.py`): принимает запрос по адресу `/api/<имя_функции>`, собирает из него событие в том же формате, вызывает `handler` нужной функции из папки `backend/<имя_функции>/index.py` и возвращает её ответ.
4. Запускать через systemd (`gunicorn`, 2 процесса), переменные окружения хранить в `/etc/arm.env` с правами 600:
   ```
   DATABASE_URL=postgresql://arm:ПАРОЛЬ@localhost:5432/arm
   MAIN_DB_SCHEMA=t_p5901577_safety_platform_deve
   UPLOAD_DIR=/var/www/uploads
   ```
5. В коде загрузки фото (`upload-photo`) и экспорта/импорта заменить обращение к хранилищу платформы на запись в локальную папку `/var/www/uploads`.

Этот шаг самый трудоёмкий, его можно поручить мне: напишу переходник и адаптацию фото.

## Шаг 5. Сайт и HTTPS

На своём компьютере или на сервере собрать сайт (`npm install && npm run build`), результат положить в `/var/www/arm`.

Настройка nginx (`/etc/nginx/sites-available/arm`):

```
server {
    server_name ВАШ_ДОМЕН;
    root /var/www/arm;
    index index.html;
    client_max_body_size 30m;

    location / { try_files $uri /index.html; }
    location /api/ { proxy_pass http://127.0.0.1:8000; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_read_timeout 60s; }
    location /uploads/ { alias /var/www/uploads/; expires 30d; }
}
```

```
sudo ln -s /etc/nginx/sites-available/arm /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d ВАШ_ДОМЕН
```

В коде сайта адреса функций (`backend/func2url.json`) заменить на `https://ВАШ_ДОМЕН/api/<имя>` до сборки.

## Шаг 6. Перенос фото

1. Скачать все файлы из хранилища платформы (папка `prescription-photos/` и другие) в `/var/www/uploads`.
2. В базе заменить старые ссылки вида `https://cdn.poehali.dev/projects/.../bucket/prescription-photos/...` на `https://ВАШ_ДОМЕН/uploads/prescription-photos/...` во всех колонках, где они хранятся.
3. Выборочно открыть 5-10 нарушений с фото и убедиться, что картинки видны.

Перед заменой ссылок сделайте копию базы: `pg_dump -Fc arm > before_urls.dump`.

## Шаг 7. Пробный запуск

- Пройтись по основным разделам: вход, предписания, проверки, приостановки, штрафы, численность, отчёты, экспорт в Excel, загрузка фото, уведомления.
- Сверить количество записей в основных таблицах со старой базой.
- Подключить резервное копирование (инструкция в `docs/BACKUP.md`) и один раз проверить восстановление.

## Шаг 8. Переключение

1. Выбрать время вне рабочих часов, предупредить пользователей.
2. Остановить работу на старой версии (отдельно сообщить, что вносить данные нельзя).
3. Повторить шаги 3 и 6 (свежая выгрузка базы и новых фото), заменить ссылки.
4. Если домен уже используется, переключить A-запись на новый IP. Обновление может занять до нескольких часов.
5. Сообщить пользователям новый адрес и проверить вход.
6. Старую версию оставить нетронутой минимум на 2 недели как запасной вариант.

## Шаг 9. После переезда

- Раз в месяц проверять восстановление из копии.
- Раз в месяц устанавливать обновления: `sudo apt update && sudo apt upgrade -y`.
- Следить за свободным местом на диске (`df -h`), особенно за ростом фото.
- Хранить пароли сервера и базы в надёжном месте, не в переписке.
